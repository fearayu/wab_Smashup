# คำถามตรวจระบบหลักและการปรับใช้

## จองสนามและข้อมูลการจอง

1. คอร์ตเดียวกัน วันและเวลาเดียวกันจองซ้ำได้ไหม? — อ่านรายการล่าสุดก่อนบันทึก ตรวจคอร์ตและเวลาเริ่ม รวมรูปแบบเวลาเก่าที่มีช่วงท้าย หากเบราว์เซอร์รองรับ Web Locks จะจัดลำดับการเขียนระหว่างหน้าต่างใน origin เดียวกัน
2. จองวันย้อนหลัง รอบที่ผ่านมา หรือเกิน 7 วันได้ไหม? — ตรวจซ้ำในกฎกลางก่อนบันทึก และใช้วันท้องถิ่นของเครื่องแทนการตัดวันที่ UTC
3. ล็อกคอร์ตหมดเวลาแล้วหน้าอื่นยังเห็นว่าจองอยู่หรือไม่? — ทุกหน้าที่อ่านรายการผ่านกฎกลางตีความรายการรอตรวจที่หมดเวลาเป็นยกเลิกเหมือนกัน อ่านใหม่เมื่อรีเฟรช กลับมายังหน้า หรือมีการเปลี่ยนข้อมูลในอีกหน้าต่าง
4. หน้าข้อมูลการจองตรงกับรายการที่ส่งจริงไหม? — เอารายการตัวอย่างที่แทรกเฉพาะในหน้าข้อมูลออก ข้อมูลที่ผู้ใช้บันทึกเดิมยังคงอยู่
5. จำนวนคอร์ตว่างหมายถึงว่างเวลาใด? — เพิ่มตัวกรองรอบเวลา สรุปไม่นับรายการยกเลิก และไม่นำการค้นหาชื่อไปเปลี่ยนจำนวนคอร์ตทั้งรอบ หากเลือกทุกเวลาอธิบายว่าเป็นการนับคอร์ตที่มีจองในวันนั้น

## บัญชีและรายการของฉัน

6. ออกจากระบบหรือเปลี่ยนบัญชีในอีกแท็บแล้วยังส่งคำขอได้ไหม? — ตรวจบัญชีปัจจุบันทุกครั้งก่อนเขียนรายการ และปฏิเสธการทำรายการจากหน้าบัญชีเก่า
7. ผู้ใช้ยกเลิกรายการของคนอื่นผ่านปุ่มได้ไหม? — ตรวจ ownerId กับบัญชีปัจจุบันก่อนบันทึกการยกเลิก
8. ดูรายการบุฟเฟต์และคำขอบริการของตัวเองได้ไหม? — รวมกับการจองสนามในรายการของฉัน พร้อมปุ่มยกเลิกตามเงื่อนไข
9. ยกเลิกตอนไหนได้? — สนามและบุฟเฟต์ก่อนเริ่มอย่างน้อย 2 ชั่วโมง คำขอซื้อสินค้า/แข่งขันได้ระหว่างรอตรวจ คำขอซ้อมต้องก่อนเวลาและยังไม่ดำเนินการเสร็จ
10. ยกเลิกเท่ากับคืนเงินหรือไม่? — ไม่ทำรายการคืนเงินอัตโนมัติ ให้ติดต่อผู้จัดหากเคยชำระเงินจริงนอกระบบ

## บุฟเฟต์และคิว

11. ลงชื่อซ้ำหรือคนเต็มรอบได้ไหม? — ตรวจบัญชี รอบ วัน จำนวนคนสูงสุด 30 และรอบของตนที่เวลาทับซ้อนก่อนบันทึก
12. คิวปนคนต่างวันหรือต่างรอบไหม? — เลือกวันและรอบก่อนจัดคิว แยกข้อมูลแต่ละรอบ รวมถึงแยกหน้ามือใหม่กับรอบปกติ
13. รายการยกเลิกยังเข้าคิวได้ไหม? — สร้างคิวจากรายการยืนยันล่าสุด และตัดรายการที่ถูกยกเลิกหรือถอนสถานะออกก่อนจัดคิว
14. สมาชิกทั่วไปแก้คิวได้ไหม? — ผู้ใช้ดูได้ ส่วนเพิ่มชื่อ จัดคิว แก้คอร์ต/ลูก และจบรอบตรวจสิทธิ์ผู้ดูแลก่อนบันทึก
15. รีเฟรชแล้วรายชื่อซ้ำหรือกลับมาหลังจบรอบไหม? — ใช้รหัสรายการระบุตัวผู้เล่น เก็บรหัสจบรอบแยกตามวัน/รอบ และตรวจการเขียนทับจากอีกหน้าต่าง
16. คอร์ตในคิวใช้เลขเดียวกับจองสนามไหม? — ใช้ 1–11, A, B จากชุดกฎกลาง
17. คิวเก่าจะหายหรือไม่? — เก็บข้อมูล v1 ไว้ ไม่ล้าง คิวที่โยงรหัสการลงทะเบียนและระบุวัน/รอบได้ถูกนำมาแสดงในรอบนั้น รายชื่อที่เพิ่มเองในคิวเก่าไม่มีวัน/รอบจึงไม่ย้ายอัตโนมัติ ผู้จัดต้องตรวจแล้วเพิ่มในรอบที่ถูกต้อง ข้อมูลใหม่เก็บใน v2

## บริการและแอดมิน

18. กรอกจำนวนติดลบ ทศนิยม หรือไม่ระบุคู่เล่นได้ไหม? — จำนวนสินค้า 1–5 ชิ้น ผู้ซ้อม 1–8 คน ต้องเป็นจำนวนเต็ม คู่ผสมต้องมีชื่อคู่เล่น ตรวจชนิดบริการและตัวเลือกที่รองรับ
19. กดส่งซ้ำทำให้เกิดรายการซ้ำไหม? — ปิดปุ่มระหว่างบันทึก และตรวจรายการซ้ำของรอบซ้อม ประเภทแข่งขัน และคำขอสินค้าที่ยังรอตรวจ
20. แอดมินเปิดหน้าครั้งแรกแล้วมีข้อมูลตัวอย่างมาปนหรือไม่? — ไม่เพิ่มข้อมูลตัวอย่างอัตโนมัติ ข้อมูลเดิมไม่ถูกลบ
21. ยืนยันรายการเท่ากับชำระเงินจริงไหม? — ไม่เปลี่ยนสถานะการชำระเงินอัตโนมัติ และปรับข้อความจองให้ตรงกับต้นแบบ
22. ชุบชีวิตรายการยกเลิกแล้วให้ชนรายการใหม่ได้ไหม? — รายการยกเลิกหรือหมดเวลาเป็นสถานะสิ้นสุด ต้องสร้างรายการใหม่และตรวจเงื่อนไขอีกครั้ง
23. ตรวจย้อนหลังใครยกเลิกหรือเปลี่ยนสถานะได้ไหม? — บันทึกบัญชีผู้ทำรายการ เวลา และสถานะก่อน/หลังไว้ในข้อมูลรายการ
24. ข้อมูลเสียหรือพื้นที่เต็มแล้วขึ้นว่าสำเร็จหรือไม่? — แจ้งข้อผิดพลาด ไม่ล้างข้อมูลเสียและไม่แสดงสำเร็จก่อนบันทึกเสร็จ

## ขอบเขตที่ยังต้องพัฒนาเพิ่มเติม

- การตรวจสิทธิ์และข้อมูลยังอยู่ฝั่งเบราว์เซอร์ ไม่ป้องกันการแก้ localStorage โดยตรง และไม่ใช่ฐานข้อมูลร่วมหลายอุปกรณ์
- ถ้าไม่มี Web Locks จะตรวจรายการล่าสุดก่อนเขียน แต่ยังไม่รับรองการจองพร้อมกันข้ามแท็บ ต้องมีธุรกรรมฝั่งเซิร์ฟเวอร์ในการใช้งานจริง
- ไม่มีการรับเงินจริง แจ้งเตือนภายนอก หรือคืนเงินจริงผ่านเว็บ การล็อก 15 นาทีเป็นการจำลองขั้นตอนรอผู้จัดยืนยัน
- สนามซ้อมและซื้อสินค้าเป็นคำขอบริการ ยังไม่ใช่การล็อกคอร์ตจริงหรือหักสต็อกสินค้า
- ฟอร์มลงทะเบียนบุฟเฟต์มือใหม่ยังเป็นหน้าข้อมูลเดิม คิวมือใหม่รองรับการเพิ่มรายชื่อโดยผู้จัดในรอบที่เลือก แต่ไม่ดึงผู้ลงทะเบียนรอบปกติไปปน
- ยังไม่มีการยืนยันการร่วมเล่นเป็นคู่ จึงไม่อ้างว่าเพิ่มระบบนัดหมาย/คำเชิญ หรือการร้องเรียนคู่เล่นในรอบนี้
