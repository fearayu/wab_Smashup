## กิตติกรรมประกาศ

โครงงานฉบับนี้สำเร็จลุล่วงไปได้ด้วยดี เนื่องด้วยความกรุณาและการให้คำปรึกษาแนะนำเป็นอย่างดียิ่งจาก ผู้ช่วยศาสตราจารย์ ดร.สุรางคนา ระวังยศ อาจารย์ที่ปรึกษาโครงงาน ที่ได้สละเวลาอันมีค่าในการถ่ายทอดความรู้ ให้ข้อเสนอแนะ และตรวจสอบความถูกต้องของเนื้อหาตลอดระยะเวลาการดำเนินงาน

คณะผู้จัดทำขอกราบขอบพระคุณเป็นอย่างสูง และขอขอบคุณคณะเทคโนโลยีสารสนเทศ มหาวิทยาลัยพะเยา ที่เอื้อเฟื้อสถานที่และอุปกรณ์สำหรับการศึกษาค้นคว้า

## บทที่ 1 บทนำ

### ที่มาและความสำคัญของโครงงาน

ในปัจจุบัน กีฬาแบดมินตันได้รับความนิยมอย่างแพร่หลายทั้งในระดับมืออาชีพและนันทนาการ โดยเฉพาะในประเทศไทยซึ่งมีผู้เล่นแบดมินตันจำนวนมากทั้งในระดับสมัครเล่นและกึ่งมืออาชีพ จากข้อมูลของสมาคมแบดมินตันแห่งประเทศไทย พบว่ามีสนามแบดมินตันเปิดให้บริการมากกว่า 3,000 แห่งทั่วประเทศ

การเล่นแบดมินตันไม่เพียงแต่เป็นการออกกำลังกายที่ดีต่อสุขภาพ แต่ยังเป็นกิจกรรมสร้างความสัมพันธ์ทางสังคม และพัฒนาทักษะการทำงานเป็นทีม

อย่างไรก็ตาม ผู้เล่นแบดมินตันในปัจจุบันยังคงเผชิญกับปัญหาหลายประการ:

**ปัญหาที่หนึ่ง: การหาคู่ต่อสู้ที่มีระดับฝีมือใกล้เคียงกัน**
- ผู้เล่นมักประสบปัญหาในการหาพาร์ทเนอร์หรือคู่แข่งที่เหมาะสม
- โดยเฉพาะในช่วงเวลาที่ต้องการเล่น ทำให้ต้องยกเลิกการเล่นหรือเสียเวลารอคอย

**ปัญหาที่สอง: ระบบการจองสนามที่ยังไม่มีประสิทธิภาพ**
- การจองสนามแบบดั้งเดิมมักอาศัยการโทรศัพท์หรือการติดต่อผ่านแอปพลิเคชันแชททั่วไป
- ไม่สามารถแสดงข้อมูลแบบเรียลไทม์และขาดระบบการจัดการที่เป็นระเบียบ

**ปัญหาที่สาม: การขาดข้อมูลสถิติการเล่น**
- ผู้เล่นไม่สามารถติดตามพัฒนาการและปรับปรุงทักษะของตนเองได้อย่างเป็นระบบ
- การเก็บสถิติแบบแมนนวลใช้เวลามากและขาดความแม่นยำ

ดังนั้น คณะผู้จัดทำจึงเห็นความสำคัญในการพัฒนา **"ระบบจองสนามแบดมินตันออนไลน์"** ที่จะช่วยแก้ไขปัญหาดังกล่าว โดยระบบจะประกอบด้วยฟังก์ชันหลัก:
1. ระบบจัดการสนามและการจอง
2. ระบบจัดการผู้ใช้และการเข้าสู่ระบบ
3. ระบบบันทึกสถิติการเล่น
4. ระบบชำระเงินออนไลน์

---

### วัตถุประสงค์ของโครงงาน

1. เพื่อพัฒนาระบบจองสนามแบดมินตันที่แสดงข้อมูลแบบเรียลไทม์และรองรับการจัดการการจองอย่างมีประสิทธิภาพ
2. เพื่อพัฒนาระบบจัดการผู้ใช้ที่มีความปลอดภัยและสะดวกต่อการใช้งาน
3. เพื่อพัฒนาระบบบันทึกและแสดงสถิติการเล่นแบดมินตันสำหรับการวิเคราะห์และพัฒนาทักษะของผู้เล่น
4. เพื่อพัฒนาระบบชำระเงินออนไลน์ที่รองรับการใช้งานในประเทศไทย

### ขอบเขตของการศึกษา

การพัฒนาระบบจองสนามแบดมินตันออนไลน์ในครั้งนี้ มีวัตถุประสงค์เพื่อสร้างระบบสารสนเทศที่รองรับทั้งการบริหารจัดการสนาม การนัดหมายผู้เล่น และการประมวลผลคะแนนการแข่งขัน โดยกำหนดขอบเขตตามบทบาทผู้ใช้งานออกเป็น 3 กลุ่มหลัก:

#### 1. ผู้เล่น (Player)
ผู้เล่นเป็นผู้ใช้งานหลักของระบบ โดยระบบจะถูกออกแบบให้รองรับการใช้งานผ่านเว็บแอปพลิเคชัน (Web Application) เพื่อความสะดวกในการเข้าถึง

**1.1 การจัดการบัญชีผู้ใช้**
- ระบบรองรับการสมัครสมาชิกและเข้าสู่ระบบผ่านอีเมล
- มีระบบยืนยันตัวตน (Authentication) และการเข้ารหัสข้อมูล (Encryption) เพื่อความปลอดภัย
- ผู้เล่นสามารถแก้ไขข้อมูลส่วนตัวได้

**1.2 การจองสนาม**
- ระบบเชื่อมต่อฐานข้อมูลสนามเพื่อแสดงข้อมูลสนามแบบเรียลไทม์
- ผู้เล่นสามารถเลือกวัน เวลา และประเภทการเล่น
- ระบบแสดงสถานะการจองทันทีหลังการยืนยัน

**1.3 การติดตามสถิติและพัฒนาการ**
- ระบบจัดเก็บข้อมูลการแข่งขันทั้งหมดและประมวลผลเป็นสถิติ
- แสดงผลในรูปแบบกราฟและรายงานสรุป

#### 2. เจ้าของสนาม (Court Owner)
เจ้าของสนามเป็นผู้ใช้งานในระดับผู้ให้บริการ โดยระบบจะรองรับการจัดการข้อมูลผ่าน Web Dashboard

**2.1 การจัดการข้อมูลสนาม**
- เพิ่ม แก้ไข หรือลบข้อมูลสนาม
- กำหนดโครงสร้างราคา ช่วงเวลา และเงื่อนไขการใช้งาน
- อัปโหลดรูปภาพสนาม

**2.2 การจัดการการจอง**
- แสดงตารางการจองแบบเรียลไทม์
- รองรับการอนุมัติหรือปฏิเสธคำขอจอง
- กำหนดช่วงเวลาปิดปรับปรุงสนาม

**2.3 การจัดการทางการเงิน**
- ระบบจัดทำรายงานรายได้แบบอัตโนมัติ
- แสดงยอดจอง รายได้รวม รายได้รายวัน/รายเดือน

#### 3. ผู้ดูแลระบบ (System Administrator)
ผู้ดูแลระบบมีหน้าที่ควบคุม ดูแล และรักษาความปลอดภัยของระบบทั้งหมด

**3.1 การจัดการผู้ใช้งาน**
- ตรวจสอบข้อมูลผู้ใช้ทั้งหมด
- จัดการข้อร้องเรียน

**3.2 การวิเคราะห์และรายงาน**
- ระบบรองรับแดชบอร์ดสถิติภาพรวม
- จำนวนผู้ใช้งานใหม่ อัตราการเติบโต และแนวโน้มการจองสนาม

#### ขอบเขตด้านเทคนิค

**แพลตฟอร์ม:**
- พัฒนาเป็น Web Application โดยใช้ Vue.js เป็น Frontend Framework
- ใช้ Hono + Cloudflare Workers เป็น Backend

**ระบบฐานข้อมูล:**
- ใช้ Cloudflare D1 (SQLite) เป็นฐานข้อมูลหลัก
- ใช้ Cloudflare KV สำหรับ Caching ข้อมูลที่เข้าถึงบ่อย

**API และบริการภายนอก:**
- รองรับ RESTful API สำหรับการเชื่อมต่อ Frontend และ Backend

**ความปลอดภัย:**
- เข้ารหัสข้อมูลสำคัญด้วย SSL/TLS
- ใช้ JWT (JSON Web Tokens) สำหรับการ Authentication
- ปฏิบัติตามกฎหมาย PDPA (Personal Data Protection Act)

### ประโยชน์ที่คาดว่าจะได้รับ

1. **ได้ระบบจองสนามแบดมินตันที่แสดงข้อมูลแบบเรียลไทม์**
   - เจ้าของสนามและผู้เล่นสามารถตรวจสอบสถานะสนามว่าง จองสนาม และบริหารจัดการตารางการใช้งานได้ทันที
   - ระบบป้องกันการจองซ้อนและแจ้งเตือนอัตโนมัติช่วยลดความผิดพลาด

2. **ได้ระบบบันทึกและแสดงสถิติการเล่น**
   - ผู้เล่นสามารถติดตามประวัติการเล่น วิเคราะห์จุดแข็งและจุดอ่อน
   - ข้อมูลสถิติช่วยให้กำหนดเป้าหมายการฝึกซ้อมได้อย่างมีทิศทาง

3. **ได้ระบบชำระเงินออนไลน์ที่สะดวกรวดเร็ว**
   - รองรับการชำระเงินผ่านระบบ PromptPay QR Code
   - ลดขั้นตอนการชำระเงินและเพิ่มความสะดวกให้กับผู้ใช้

### ขั้นตอนการดำเนินงาน

#### 1. การศึกษาข้อมูลและวิเคราะห์ความต้องการ (สัปดาห์ที่ 1-2)
- สำรวจความต้องการของผู้เล่นแบดมินตันผ่านแบบสอบถาม
- สัมภาษณ์เจ้าของสนามเพื่อเข้าใจปัญหาและความต้องการ
- ศึกษาแอปพลิเคชันที่มีอยู่ในตลาด (Court Reserve, Playo)
- วิเคราะห์จุดแข็ง จุดอ่อน และโอกาสในการพัฒนา

#### 2. การออกแบบระบบ (สัปดาห์ที่ 3-4)
- ออกแบบสถาปัตยกรรมระบบแบบ Client-Server
- ออกแบบฐานข้อมูล (Database Schema) สำหรับข้อมูลผู้ใช้ สนาม การจอง
- ออกแบบ User Interface และ User Experience (UI/UX)
- สร้าง Wireframe และ Mockup ของทุกหน้าจอ

#### 3. การพัฒนาระบบ Backend (สัปดาห์ที่ 5-7)
- ตั้งค่า Cloudflare Workers และ D1 Database
- พัฒนา RESTful API สำหรับ Authentication และจัดการข้อมูล
- พัฒนาระบบจองสนามแบบ Real-time
- เขียน Unit Test และ Integration Test

#### 4. การพัฒนา Frontend (สัปดาห์ที่ 8-10)
- สร้างโปรเจกต์ด้วย Vue.js และ Vuetify
- พัฒนาหน้าจอ Authentication (Login, Register)
- พัฒนาหน้าจองสนาม (Browse, Book, Payment)
- พัฒนาหน้าแสดงสถิติและประวัติการเล่น

#### 5. การทดสอบระบบ (สัปดาห์ที่ 11-12)
- Unit Testing และ Integration Testing
- System Testing ในสถานการณ์การใช้งานจริง
- User Acceptance Testing (UAT) กับผู้ใช้จริง
- แก้ไข Bug และปรับปรุงตาม Feedback

#### 6. การ Deploy และเผยแพร่ (สัปดาห์ที่ 13)
- Deploy ระบบบน Cloudflare (Workers + Pages)
- ตั้งค่า Production Environment
- จัดทำเนื้อหาการตลาด (Video Demo, Screenshots)

   - Cloudflare Pages: Frontend Deployment
   - Wrangler CLI: เครื่องมือจัดการ Cloudflare

## บทที่ 2 เอกสารและงานวิจัยที่เกี่ยวข้อง

### ทฤษฎีและหลักการที่เกี่ยวข้อง

#### Web Application Architecture
Web Application คือ แอปพลิเคชันที่ทำงานผ่านเว็บเบราว์เซอร์ โดยไม่ต้องติดตั้งซอฟต์แวร์บนเครื่องผู้ใช้ สถาปัตยกรรมที่นิยมใช้ในปัจจุบันคือ Client-Server Architecture ซึ่งประกอบด้วย:

- **Frontend (Client-side)**: ส่วนที่ผู้ใช้เห็นและโต้ตอบ พัฒนาด้วย HTML, CSS, JavaScript
- **Backend (Server-side)**: ส่วนประมวลผลข้อมูล จัดการฐานข้อมูล และตอบสนองต่อคำขอจาก Client
- **Database**: ระบบจัดเก็บข้อมูล เช่น SQLite, PostgreSQL

#### RESTful API
REST (Representational State Transfer) คือ รูปแบบการออกแบบ API ที่ใช้ HTTP Methods (GET, POST, PUT, DELETE) เพื่อจัดการทรัพยากรในระบบ โดยมีหลักการสำคัญ:
- Stateless: แต่ละคำขอเป็นอิสระจากกัน
- Resource-based: ทรัพยากรถูกระบุด้วย URL
- Representation: ข้อมูลส่งผ่านในรูปแบบ JSON หรือ XML

#### Single Page Application (SPA)
SPA คือ เว็บแอปพลิเคชันที่โหลดหน้าเดียวและอัปเดตเนื้อหาแบบไดนามิกโดยไม่ต้องรีโหลดทั้งหน้า ข้อดี:
- ประสบการณ์ผู้ใช้ที่ราบรื่น (UX ดี)
- ลดการโหลดข้อมูลจากเซิร์ฟเวอร์
- รองรับการทำงานแบบ Offline ได้บางส่วน

---

### งานวิจัยที่เกี่ยวข้อง

#### 1. Real-Time Court Booking System Design
Wijaya และ Santoso (2024) ได้พัฒนาระบบจองสนามกีฬาแบบเรียลไทม์ที่มีกลไกการแก้ไขความขัดแย้งเมื่อมีการจองพร้อมกัน โดยใช้ Optimistic Locking และ Transaction Management

**ประโยชน์ต่อโครงงาน**: เทคนิคการป้องกันการจองซ้ำและการออกแบบ UI สามารถนำมาประยุกต์ใช้ได้

#### 2. User Experience Design for Sports Booking Applications
Park และ Kim (2023) ได้ศึกษาปัจจัยที่ส่งผลต่อ User Experience ในแอปพลิเคชันจองสนามกีฬา โดยพบว่าปัจจัยสำคัญได้แก่:
- ความเร็วในการโหลดและการตอบสนอง
- ความชัดเจนของข้อมูลสนาม
- กระบวนการจองที่ง่ายและรวดเร็ว (ไม่เกิน 3 ขั้นตอน)
- ระบบแจ้งเตือนที่ตรงเวลา

**ประโยชน์ต่อโครงงาน**: แนวทางเหล่านี้จะถูกนำมาใช้ในการออกแบบ UI/UX ของระบบ

#### 3. Lightweight Web Framework for Edge Computing
การใช้ Cloudflare Workers ซึ่งเป็น Edge Computing Platform ช่วยลด Latency และเพิ่มประสิทธิภาพในการตอบสนองต่อคำขอของผู้ใช้ โดยเฉพาะระบบที่ต้องการความเร็วสูงอย่างการจองสนามแบบเรียลไทม์

### รีวิวแอปพลิเคชัน

#### 1. Court Reserve
แอปพลิเคชันมุ่งเน้นการจองสนามกีฬาหลายประเภท รวมถึงแบดมินตัน เทนนิส สควอช

**ฟีเจอร์หลัก**:
- แสดงรายการสนามพร้อมรูปภาพ ราคา และรีวิว
- ตารางเวลาว่างแบบเรียลไทม์
- ระบบจองและชำระเงินออนไลน์

**จุดเด่น**: สนามมีให้เลือกหลากหลาย ระบบจองทำงานได้เร็ว
**จุดด้อย**: ไม่มีระบบจัดการผู้เล่นและสถิติการเล่น

#### 2. Playo
แอปพลิเคชันกีฬาที่ครอบคลุมหลายกีฬา มีฟีเจอร์ทั้งการหาคู่เล่น การจองสนาม

**ฟีเจอร์หลัก**:
- จับคู่ผู้เล่นและสร้างกลุ่มเล่น
- จองสนามผ่านแอปพลิเคชัน
- บันทึกคะแนนการเล่นแบบ Manual

**จุดเด่น**: ครอบคลุมหลายฟีเจอร์ในแอปเดียว
**จุดด้อย**: การนับแต้มยังต้องทำ Manual UI ซับซ้อน
