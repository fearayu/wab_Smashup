# SMASHUP — กฎธุรกิจในโค้ด: การหาคู่เล่นตามระดับ / ระบบระดับผู้เล่น

> เอกสารนี้สรุปจาก `shared/match-core.js`, `shared/player-levels.js` และนโยบาย `docs/player-assessment-policy.md` ยืนยันด้วย `tests/match-core.test.cjs`, `tests/player-assessment.test.cjs`

## 1. คะแนนจับคู่ (Matchmaking) — deterministic ไม่ใช่ AI

สูตร: **total = skill×0.7 + schedule×0.15 + travel×0.15**

| องค์ประกอบ | น้ำหนัก | วิธีคิด | หมายเหตุ |
|---|---|---|---|
| skill | 70% | ระดับเดียวกัน = 100, ห่าง 1 ชั้น = 65, ห่าง >1 ชั้น = 30 | ใช้ ladder ค่า 1–9 |
| schedule | 15% | เวลาสะดวกตรงกัน = 100, ห่างกันชั่วโมงละลด 15 (ขั้นต่ำ 40) | ต้องระบุเวลาถึงจะนับ |
| travel | 15% | `100 − (ระยะ/ระยะสูงสุด)×100` | ไม่รู้ระยะ = กลางๆ 50 **ไม่เคยปั้นข้อมูล** |

- ผลลัพธ์ `{ total, skill, schedule, travel, gap, reasons[] }` — แสดงเหตุผลทุกใบ แปลงให้ผู้ใช้เข้าใจ (เช่น "ระดับเดียวกัน", "เวลาที่สะดวกตรงกัน", "ระยะทางใกล้")
- ไม่ใช่ AI และไม่รับประกันว่าจะเจอคู่; ใช้ข้อมูลที่ผู้ใช้กรอกจริง + ระดับที่ผู้จัดยืนยัน
- bucket สำหรับตัวกรอง: beginner (≤3) / intermediate (4–6) / advanced (≥7)

## 2. Ladder ระดับผู้เล่น

| รหัส | ชื่อ |
|---|---|
| N | ยังไม่ทราบ |
| S/BG | ผู้เริ่มต้น |
| P- / P / P+ | มือพื้นฐาน |
| C / C+ | มือกลาง |
| B/B+ | มือดี |
| A/Pro | มือเก่ง/โปร |

## 3. การประเมินและยืนยันระดับ (`shared/player-levels.js`)

- แบบประเมิน **6 ด้าน** (พื้นฐานตีลูก เท้า-การเคลื่อนที่ เสิร์ฟ/รับเสิร์ฟ ฯลฯ) → คำนวณระดับ N–A/Pro
- ผู้จัดต้อง **สังเกตการเล่นอย่างน้อย 2 เกม** จึงจะยืนยันระดับให้ทางการได้
- สถานะ: ยังไม่ประเมิน → ประเมินเอง (`self-assessed`) → ผู้จัดยืนยัน (`organizer-confirmed`); มี `request/defer/resolve` เมื่อความเห็นไม่ตรง และบันทึก **ประวัติ/หลักฐาน**
- ระดับที่ผู้จัดยืนยันจะชนะระดับที่กรอกเอง เวลาระบบอ่านระดับ (เช่น ลงบุฟเฟต์มือ C เท่านั้น)

## 4. กฎที่ผูกกับระดับ

- บุฟเฟต์บางรอบ/การแข่งขัน: เปิดรับเฉพาะระดับที่กำหนด (ปิดรับมืออื่น)
- การหาคู่: คะแนน skill ใช้ระดับจริง + เหตุผลโปร่งใส
- การจัดสายแข่ง: **จัดสายตามระดับมือ** — มือเก่งเป็นหัวสายกระจายกัน (ไม่ชนกันรอบแรก) แล้วสุ่มสลับภายในระดับเดียวกัน

## 5. หลัก "ซื่อตรงต่อข้อมูล"

- ข้อมูลไม่ครบ → ให้ค่ากลาง (50) หรือเหตุผล "ยังไม่ระบุ" **ไม่เดา/ไม่ปั้น**
- การตัดสินใจทำแบบ deterministic → ตรวจสอบย้อนกลับได้ทุกค่า (ต่างจาก black-box)
- ผู้จัดยืนยันระดับตามเกมจริง ไม่ใช่ให้ผู้เล่น key เข้าไปเอง
