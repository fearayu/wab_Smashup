# คู่มือหน้าเว็บ SMASHUP

เอกสารนี้อธิบายหน้าจอหลักของระบบ SMASHUP Badminton Project, ผู้ใช้งานของแต่ละหน้า, การทำงานสำคัญ และไฟล์ที่เกี่ยวข้อง

## ภาพรวม User Flow

```text
หน้าแรก
  -> เข้าสู่ระบบ
  -> เลือกบริการ
       -> จองสนาม -> เลือกวัน/เวลา/คอร์ต -> ยืนยัน -> รายการของฉัน
       -> ตีบุฟเฟต์ -> เลือกรอบ -> ลงทะเบียน -> คิวบุฟเฟต์
       -> หาคู่เล่น -> กรองผู้เล่น -> ส่งคำเชิญ -> นัดหมาย
       -> ผู้ดูแล -> ตรวจรายการ -> ยืนยัน/ยกเลิก -> รายงาน
```

ปัจจุบันหน้าเว็บเป็น static prototype และเก็บข้อมูลใน `localStorage` เป็นหลัก
กฎการจองและสิทธิ์ส่วนกลางอยู่ที่ `shared/service-rules.js` ส่วนจุดต่อ backend อยู่ที่ `shared/api.js`

## Authentication และโปรไฟล์

### `auth/index.html`

หน้าเข้าสู่ระบบ/สมัครสมาชิกหลัก รองรับ `?next=...` เพื่อพาผู้ใช้กลับไปยังหน้าที่ต้องการหลัง login มีบัญชีเดโมสำหรับทดสอบระบบ

- ใช้ [auth/auth.js](../auth/auth.js)
- session เดโมเก็บใน `smashup_session_v1`
- ผู้ดูแลจะถูกพาไป `admin/index.html`
- ผู้เล่นทั่วไปจะถูกพาไปหน้าแรกหรือ URL ใน `next`

### `auth/login.html` (legacy/alternate)

หน้า login/register อีกเวอร์ชันที่มีฟอร์มโปรไฟล์ผู้เล่น เช่น ระดับ เป้าหมาย และเวลาที่สะดวก ปัจจุบันซ้ำกับ `auth/index.html` และควรกำหนดให้เหลือ entry point เดียวในอนาคต

### `auth/player-assessment.html`

แบบประเมินระดับฝีมือและหน้าสำหรับผู้จัดยืนยันระดับ เชื่อมกับระบบ matching เพื่อระบุที่มาของระดับว่าเป็นการประเมินเองหรือผู้จัดยืนยัน

- ใช้ [auth/player-assessment.js](../auth/player-assessment.js)
- ใช้ `shared/player-levels.js`

## การจองสนาม

### `booking/index.html` (หน้าหลัก)

ตารางจองสนามหลัก แสดง 13 คอร์ตและ 3 ช่วงเวลาในช่วง 7 วัน ผู้ใช้เลือกวัน จากนั้นกดคอร์ตที่ว่างเพื่อเปิด dialog กรอกชื่อและเบอร์โทร

ผลลัพธ์หลังจอง:

1. ตรวจ session และข้อมูลติดต่อ
2. ตรวจวัน เวลา คอร์ต และรายการซ้ำ
3. บันทึกสถานะ `รอตรวจสอบ`
4. ปิด dialog และแสดงข้อความสำเร็จ
5. คอร์ตที่จองแล้วจะเปลี่ยนเป็น `จองแล้ว`

หน้าดังกล่าวเป็นทางเข้าหลักของระบบจองและควรใช้เป็นต้นแบบต่อไป

### `booking/form.html`

ฟอร์มจองสนามแบบกรอกข้อมูลโดยตรง ผู้ใช้เลือกวัน เวลา และจำนวนคอร์ต ระบบคำนวณราคาโดยประมาณ จากนั้นแสดง dialog ยืนยัน

- ใช้ [booking/booking.js](../booking/booking.js)
- มีตัวกันการ submit ซ้ำ
- เชื่อมกับ [booking/my-bookings.html](../booking/my-bookings.html)

### `booking/court-booking.html` (legacy/alternate)

ตารางจองสนามอีกเวอร์ชันที่มีโครงสร้างใกล้กับ `booking/index.html` แต่ใช้ markup และ flow คนละชุด ปัจจุบันควรรวมให้เหลือ `booking/index.html` เพราะเมนูหลักใช้หน้านั้น

### `booking/booking-info.html`

หน้าข้อมูลบริการจองสนาม เช่น ราคา จำนวนคอร์ต และช่วงเวลา เหมาะสำหรับอ่านรายละเอียดก่อนเริ่มจอง ไม่ใช่หน้าทำรายการโดยตรง

### `booking/rules.html`

หน้ากฎการใช้สนาม เช่น จองล่วงหน้า 7 วัน ต้องยืนยันภายใน 15 นาที และเงื่อนไขการยกเลิก

## ตีบุฟเฟต์

### `booking/buffet-registration.html` (flow หลัก)

หน้าลงทะเบียนตีบุฟเฟต์ เลือกรอบ เวลา ระดับ และตัวเลือกค่าลูก จากนั้นรับหมายเลขคิวและสามารถยกเลิกได้

### `booking/regular-buffet-booking.html`

ฟอร์มตีบุฟเฟต์อีกเวอร์ชันที่เชื่อมกับ `regular-buffet-info.html` และ `regular-buffet-queue.html` ใช้กฎระดับผู้เล่นและ service rules ร่วมกัน

### `booking/regular-buffet-info.html`

แสดงรายชื่อผู้ลงทะเบียน กรองตามวัน/ชื่อ และเชื่อมไปหน้าจัดคิว เหมาะกับผู้จัดมากกว่าผู้เล่นทั่วไป

### `booking/regular-buffet-queue.html`

หน้าผู้จัดสำหรับแบ่งสนาม แบ่งลูก จบรอบ และดูประวัติคิว ผู้เล่นสามารถดูสถานะคิวได้ตามสิทธิ์

### `booking/buffet-booking.html`, `booking/buffet-info.html`, `booking/buffet-queue.html`

เป็นชุดหน้า buffet รุ่นเดิมที่มีหน้าข้อมูลและหน้าคิวคล้ายกับกลุ่ม `regular-*` ควรถือเป็น legacy จนกว่าจะรวม flow เสร็จ

### `booking/beginner-buffet-booking.html`, `beginner-buffet-info.html`, `beginner-buffet-queue.html`

ชุดหน้าสำหรับบุฟเฟต์มือใหม่ ใช้ข้อความและธีมเฉพาะกลุ่ม แต่มีความซ้ำกับ flow บุฟเฟต์หลัก ควรตรวจว่าจำเป็นต้องแยกเป็นบริการจริงหรือไม่

## บริการอื่นใน Booking

### `booking/practice.html`

หน้าข้อมูลจองสนามซ้อม ปัจจุบันยังไม่มีฟอร์มสนามซ้อมเฉพาะและยังพาไป flow จองสนามทั่วไป

### `booking/tournament.html`

หน้าจัดการแข่งขันแบบครบวงจร: สร้างรายการแข่ง, สมัคร/ยกเลิกสมัครตามประเภทและระดับ, **จัดสายตามระดับมือ** (มือเก่งเป็นหัวสาย กระจายไม่ชนรอบแรก + สุ่มสลับภายในระดับเดียวกัน, Bracket R32→R16→รอบรอง→ชิงฯ), เลื่อนผู้ชนะขึ้นรอบอัตโนมัติ, บันทึกผล/คะแนน และคำนวณอันดับ 1/2/3

- ใช้ [shared/tournament.js](../shared/tournament.js)
- มีชุดทดสอบ [tests/tournament.test.cjs](../tests/tournament.test.cjs)

### `booking/shop.html`

หน้าข้อมูลลงชื่อซื้อสินค้า ปัจจุบันยังไม่มี checkout หรือระบบชำระเงินจริง

## Matching และนัดหมาย

### `matching/index.html` (หน้าหลัก)

ค้นหาผู้เล่นจากระดับ รูปแบบการเล่น วัน เวลา และระยะทาง ระบบคำนวณ Match % แล้วส่งคำเชิญได้

- ใช้ [matching/matchmaking.js](../matching/matchmaking.js)
- สูตรคะแนนอยู่ที่ `shared/match-core.js`
- คำเชิญอยู่ที่ `shared/appointments.js`

### `matching/player-matching.html` (legacy/prototype)

เครื่องมือคำนวณความเหมาะสมแบบกรอกข้อมูลผู้เล่นเอง เพิ่มผู้เล่นหลายคนและบันทึก filter ใน browser แต่ไม่มี pool ผู้ใช้จริงหรือ flow ส่งคำเชิญ ควรใช้ `matching/index.html` เป็นหน้าหลัก

### `appointments/index.html`

หน้าคำเชิญและนัดหมายของฉัน แบ่งเป็นแท็บคำเชิญกับตารางนัดหมาย ผู้ใช้สามารถตอบรับ ปฏิเสธ ยกเลิก และส่งคำเชิญได้

หมายเหตุ: นัดหมายจาก matching ไม่ใช่การจองคอร์ตจริง ต้องจองสนามแยกใน booking flow

## ไฟล์ส่วนกลางที่ควรรู้

- `shared/service-rules.js`: กฎวัน/เวลา ตรวจคอร์ตซ้ำ การยกเลิก ownership และสถานะรายการ + แจ้งเตือนเมื่อจอง/สถานะเปลี่ยน
- `shared/appointments.js`: สร้างและตอบรับคำเชิญนัดหมายโดยผูกกับ user id + แจ้งเตือนผู้รับ/ผู้ส่ง
- `shared/tournament.js`: การแข่งขัน/จัดสาย (สร้าง, สมัคร, **จัดสายตามระดับมือ**, Bracket, ผล, อันดับ)
- `shared/notifications.js`: สร้าง/อ่าน/กดอ่านการแจ้งเตือนในแอป
- `shared/notify-ui.js`: ระฆังแจ้งเตือน + ป้ายตัวเลข + แผงรายการบน header ทุกหน้า
- `shared/player-levels.js`: ระดับผู้เล่น แบบประเมิน และการยืนยันโดยผู้จัด
- `shared/auth-ui.js`: แสดง login/logout ใน header ของแต่ละหน้า
- `shared/admin-guard.js`: ตรวจสิทธิ์ผู้ดูแล
- `shared/api.js`: จุดต่อ backend สำหรับ API mode; โหมดเดโมปัจจุบันยังใช้ localStorage
- `shared/app-shell.css`: topbar, sidebar, ปุ่ม และ responsive shell
- `shared/theme.css`: token สีและ visual theme ร่วมของระบบ

## หน้าที่ซ้ำและข้อเสนอแนะการจัดเส้นทาง

ได้จัดเส้นทาง canonical ให้เหลือชุดดังต่อไปนี้ และ**หน้า legacy ถูกเปลี่ยนเป็น redirect** ไปหาหน้า canonical แล้ว:

- Login: `auth/index.html`
- Court booking: `booking/index.html` (เดิม `court-booking.html` → redirect)
- Buffet: `booking/buffet-registration.html` (เดิม `buffet-booking.html`, `regular-buffet-booking.html`, `beginner-buffet-*` → redirect)
- Buffet queue/info: `regular-buffet-queue.html`, `regular-buffet-info.html` (หน้าเก่า → redirect)
- Matching: `matching/index.html` (เดิม `player-matching.html` → redirect)
- Tournament: `booking/tournament.html` (ใช้งานได้แล้ว — สมัคร/จัดสาย/ผล/อันดับ)
- Admin dashboard: `admin/index.html`
