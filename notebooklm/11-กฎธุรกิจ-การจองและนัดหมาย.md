# SMASHUP — กฎธุรกิจในโค้ด: การจองสนาม / ตีบุฟเฟต์ / บริการ / นัดหมาย

> เอกสารนี้สรุปจาก `shared/service-rules.js` และ `shared/appointments.js` (เป็นตรรกะเดียวกับที่หน้าเว็บใช้จริงและที่ทดสอบใน `tests/`)

## 1. Key ที่เก็บข้อมูล (localStorage)

| ข้อมูล | Key |
|---|---|
| การจองสนาม (court) | `smashup_bookings_v1` |
| การลงทะเบียนบุฟเฟต์ | `smashup_buffet_bookings_v1` |
| คำขอใช้บริการ (แข่ง/ซ้อม/ของ) | `smashup_service_requests_v1` |
| คิวบุฟเฟต์ | `smashup_buffet_queue_v2` |
| ผู้ใช้ | `smashup_users_v1` |
| Session (ล็อกอิน) | `smashup_session_v1` |
| คำเชิญ/นัดหมาย | `smashup_appointments_v1` |

ทุกการเขียนข้อมูลผ่านฟังก์ชัน `write()`/`mutate()` ตรงกลาง เพื่อ:
- อ่านแล้ว **normalize** ทุกรายการ (ข้ามรายการที่หมดสถานะยืนยัน → สถานะ "ยกเลิกแล้ว")
- **ล็อกแบบ async** ด้วย `navigator.locks` (key prefix `smashup:`) กันการเขียนพร้อมกัน
- ส่ง event `smashup-data` ทุกครั้งที่มีการเปลี่ยนข้อมูล ให้ทุกหน้า refresh UI เอง

## 2. สถานะของรายการจอง (Status lifecycle)

สถานะเริ่มต้น: **"รอตรวจสอบ"** (ผู้ใช้จองเข้ามา) → ผู้ดูแล "ยืนยันแล้ว" หรือ "ยกเลิกแล้ว"

สถานะที่ถือว่า "รอกระทำ/ยัง active" ได้แก่: `รอยืนยัน`, `รอตรวจสอบ`, `รอตรวจสอบการชำระเงิน`, `รอชำระเงิน`

**การหมดเวลายืนยันแบบจำลอง (15 นาที):** ทุกรายการจองมี `paymentDueAt = createdAt + 15 นาที` ถ้าเลยเวลานี้และยังไม่ยืนยัน → อัตโนมัติกลายเป็น **"ยกเลิกแล้ว"** โดย `cancelReason = "หมดเวลายืนยันรายการจำลอง"` (จำลองขั้นตอนรอผู้ดูแลยืนยัน/ชำระเงิน)

ทุกการเปลี่ยนสถานะบันทึกใน `history[]` เช่น `{ action: 'status', from, to, actor, at }`

## 3. กฎการสร้างรายการ (สร้างไม่ได้ถ้าขัดเงื่อนไข)

**จองสนาม `bookCourt`**
- คอร์ต/วัน/เวลาต้องมีจริงในตารางสนาม
- **กันการจองซ้ำ**: ถ้าวัน-เวลา-คอร์ต ชนกับรายการอื่นที่ยัง active → error
- ราคา fixed 130 ฿; ต้องส่งเวลาเริ่ม < เวลาสิ้นสุด

**ตีบุฟเฟต์ `bookBuffet`**
- รอบ (`session`) ต้องมีจริง กันสมัครซ้ำรอบเดียวกัน/เวลาทับซ้อน
- ดึง `level` จากโปรไฟล์ (ที่มาของระดับ: `organizer-confirmed` หรือ `self-assessed` หรือยัง pending)
- ค่าลูก `shuttle` + ฿60 ค่าเข้าหน้าสนาม
- บันทึกแจ้งเตือนทันที: "ลงชื่อตีบุฟเฟต์แล้ว"

**ใช้บริการ `requestService`** (สมัครแข่ง/จองซ้อม/ซื้อของ)
- ตรวจรายการซ้ำ/ข้อมูลไม่ถูกต้องก่อนสร้าง

**คิวบุฟเฟต์:** ระบบจัดการคิวแยก (key `smashup_buffet_queue_v2`)

## 4. กฎการยกเลิก (cancel)

- **ยกเลิกได้เฉพาะรายการของตัวเอง** (`ownerId === who.id`) — ตรวจใน domain ไม่ใช่แค่ซ่อนปุ่ม
- **ยกเลิกไม่ได้ถ้า:** เริ่มภายใน 2 ชั่วโมง หรือรายการถูกดำเนินการ/จบไปแล้ว
- ยกเลิกแล้ว → สถานะ **"ยกเลิกแล้ว"** + `cancelReason: 'ผู้ใช้ยกเลิก'`

## 5. กฎของผู้ดูแล (setStatus)

- เปลี่ยนสถานะได้เฉพาะ `service`: "ดำเนินการแล้ว"/"ยกเลิกแล้ว"; อื่นๆ: "ยืนยันแล้ว"/"ยกเลิกแล้ว"
- **เช็คซ้ำก่อนยืนยัน**: ยืนยัน court → ตรวจคอร์ตชนรายการ active อื่น; ยืนยัน buffet → นับ active รายการที่วัน+รอบเดียวกัน ต้อง < 30 (ไม่ให้เกินความจุ)
- รายการที่ "ยกเลิกแล้ว"/หมดเวลา → เปลี่ยนสถานะต่อไม่ได้

## 6. การนัดหมาย / คำเชิญ (`shared/appointments.js`)

- **สถานะ:** `pending` → `accepted` / `declined` / `cancelled` / `deleted`, และ `auto-cancelled` (หมดอายุ 7 วัน)
- คำเชิญผูก `senderId`+`receiverId`; ดูเฉพาะรายการของตัวเอง
- ส่งคำเชิญ → แจ้งเตือนผู้รับ; accept/decline → แจ้งเตือนผู้ส่ง
- **คำเชิญไม่ใช่การจองคอร์ตจริง** — เป็นข้อตกลงระหว่างผู้เล่น
