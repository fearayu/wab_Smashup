# SMASHUP Badminton Project

เว็บต้นแบบ (Prototype) สำหรับ **ระบบจองสนามแบดมินตันและช่วยค้นหาคู่เล่นตามระดับฝีมือและเวลาว่าง** ใช้เป็นโครงงานวิทยาการคอมพิวเตอร์ (ภาคนิพนธ์) ออกแบบให้ใช้งานง่ายบนมือถือและเดสก์ท็อปด้วยโทนสีส้ม ดำ และขาว

## ระบบหลัก 2 กระแสงาน (Core Flows)

### A. ระบบจองสนาม — `booking/` (Flow A)
- เลือกหมายเลขคอร์ต วัน และรอบเวลา แล้วตรวจคอร์ตซ้ำก่อนบันทึกทุกครั้ง
- กฎการจอง (วันย้อนหลัง/เกิน 7 วัน, คอร์ตชน, ยกเลิกก่อนเริ่ม 2 ชม., หมดเวลายืนยัน 15 นาที) อยู่ที่ `shared/service-rules.js` ฝั่งเดียว ทุกหน้าเรียกผ่านจุดเดียวกัน
- รายการของฉันรวม คอร์ต / ตีบุฟเฟต์ / คำขอบริการ และปุ่มยกเลิกตามเงื่อนไข อยู่ที่ `booking/my-bookings.html`
- ลูกค้า**เห็นและแก้ได้เฉพาะรายการของตนเอง** (`R.own(type, who)` ในกฎกลาง) ผู้ดูแลเท่านั้นยืนยัน/ยกเลิกรายการ

### B. ระบบหาคู่เล่น — `matching/` (Flow B)
- `matching/index.html` + `shared/match-core.js`: คะแนนจับคู่ **deterministic** (ระดับ 70% + เวลาที่สะดวก 15% + ระยะทาง 15% เป็นค่าทดลอง) พร้อมแสดงเหตุผลและที่มาของระดับ (ผู้จัดยืนยัน / ประเมินเอง / ไม่ยืนยัน)
- เมื่อเจอคู่ที่ตรงกัน ส่งคำเชิญได้ที่หน้า "นัดหมาย" (`shared/appointments.js`) — **ผูกกับ id ผู้รับ** ไม่พึ่งชื่อแสดงผล ตอบรับ/ปฏิเสธ/ยกเลิกได้ และหมดอายุอัตโนมัติใน 7 วัน
- ข้อมูลผู้เล่นสาธิตจะแสดงเฉพาะเมื่อยังไม่มีผู้ใช้จริง และติดป้าย "สาธิต — ไม่สามารถส่งคำเชิญ"

## สถานะการเชื่อมต่อ Backend (ความจริง)

- หน้าบ้านทั้งหมดเป็น Static HTML/JS รันบน **โหมดเดโม (localStorage ของเบราว์เซอร์)** — ยังไม่มีการเรียก API จากหน้าเว็บใด ๆ
- `backend/` (Hono + Cloudflare Workers + D1 + KV) มีโค้ดครบและ **ตรวจผ่านแล้ว**: `npm run typecheck` ผ่าน, `npm run build:lambda` ผ่าน (783 KB), `npm run smoke` รันจริงแล้วผ่าน (health / register / login / auth/me / 401 ผิดรหัส) ด้วยหน่วยความจำชั่วคราว
- จุดต่อระหว่างหน้าเว็บกับ backend คือ `shared/api.js` (seam API mode) — โหมด API จะ **ไม่เขียน localStorage เลย** และเมื่อเชื่อมต่อไม่ได้จะแจ้ง error ทันที ไม่ล้มทั้งอย่างเงียบ ๆ (ไม่มี silent fallback)
- ยังไม่ได้: กำหนดค่าวิกฤตจริงให้หน้าเว็บใช้ API mode, D1 migrations บนเครื่องผู้ใช้, และการ deploy ขึ้น Cloudflare

## ทดสอบผ่านหน้าจอ (Browser E2E)

รันล่วงหน้าจริงในเบราว์เซอร์ headless (Edge/Chrome) ผ่าน `tests/e2e/run-e2e.mjs` — ผลปัจจุบันบันทึกใน `tests/e2e/e2e-report.txt` (**24/24 ผ่าน**)

```bash
python -m http.server 4173                    # เปิด server ก่อน
npm i puppeteer-core                          # ติดตั้งในโฟลเดอร์ที่วางตัวสคริปต์ (ESM หา node_modules จากตำแหน่งตัวสคริปต์เอง)
node tests/e2e/run-e2e.mjs                    # ต้องแก้ path EDGE/CHROME ในสคริปต์ตามเครื่อง
```

> วิธีง่ายสุด: สร้างโฟลเดอร์เปล่า `npm i puppeteer-core` แล้วคัดลอก `tests/e2e/run-e2e.mjs` ไปรันในนั้น

ครอบคลุม: (A1) ล็อกอินแบบเดโม → จองคอร์ตบนตาราง → คอร์ตแสดง "จองแล้ว" → จองซ้ำถูกกัน → ยกเลิกแล้วคอร์ตว่างอีกครั้ง; (A2) ฟอร์ม `form.html` → แสดงในรายการของฉัน; (A3) ผู้ดูแล: สถิติจากข้อมูลจริง → ยืนยันรายการ → รายได้/รอดำเนินการเปลี่ยน; (B) สมัครผู้เล่นจริง 2 คน → ระบบแนะนำคู่ + Match % → ส่งคำเชิญ → อีกฝ่ายตอบรับ → ตารางนัดหมายยืนยันแล้ว

## โครงสร้างไฟล์สำคัญ

```text
.
├── index.html              # หน้าแรก (แนะนำสนาม/โปรโมชัน)
├── shared/
│   ├── service-rules.js    # กฎกลาง: คอร์ต/บุฟเฟต์/บริการ + own() ตรวจเจ้าของ
│   ├── player-levels.js    # ระดับ N–A/Pro + แบบประเมิน + ประวัติผู้จัดยืนยัน
│   ├── match-core.js       # สูตรคะแนนจับคู่ deterministic
│   ├── appointments.js     # คำเชิญ/นัดหมาย (ผูก id ผู้รับ, หมดอายุ 7 วัน)
│   ├── api.js              # seam demo/API — API mode ไม่เขียน localStorage
│   └── app-shell.css, admin-guard.js, auth-ui.js, utils.js
├── auth/                   # ล็อกอิน/สมัครสมาชิก + ประเมินระดับ (player-assessment.html)
├── booking/                # จองสนาม, ตีบุฟเฟต์, รายการของฉัน, ข้อมูลการจอง, ร้านค้า
├── matching/               # หาคู่เล่น (index.html + matchmaking.js)
├── appointments/           # นัดหมายของฉัน
├── admin/                  # แดชบอร์ดผู้ดูแล (แสดงข้อมูลจริง ไม่มีตัวเลขปลอม)
├── tests/                  # node --test 7 ชุด/116 ตรวจ + tests/e2e (บราวเซอร์ E2E 24 ตรวจ)
└── backend/                # Hono API (Clean Architecture, ยังไม่เชื่อมหน้าเว็บ)
```

ล็อกอินที่ `auth/index.html` — ระบบเป็นเดโม เก็บ session ใน `localStorage` เท่านั้น

| บัญชี | รหัสผ่าน | สิทธิ์ | หลังล็อกอิน |
|---|---|---|---|
| `admin` | `12345` | admin | `admin/index.html` |
| `customer01` | `123456` | user | หน้าแรก |
| `player01` | `player123` | user | หน้าแรก |
